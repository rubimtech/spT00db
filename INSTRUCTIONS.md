# Инструкция к парсеру нормативных документов

Парсер берёт PDF норматива (СНиП/СП/ГОСТ/СанПиН) и кладёт его в базу так, чтобы
агент-проверяющий мог спрашивать: «есть ли пункт про предел огнестойкости
воздуховодов» — и получать готовую цитату с номером пункта и страницы.

Вся работа — четыре команды. Ниже: как их вызывать, что считать успехом и что
делать, когда что-то пошло не так.

---

## 1. Окружение

```bash
# рабочий каталог
cd /d/DEV/spT00db

# питон проекта (venv Hermes — там уже pymupdf4llm, qdrant_client, onnxruntime)
PY="C:/Users/olegs/AppData/Local/hermes/hermes-agent/venv/Scripts/python.exe"

# ставить пакеты ТОЛЬКО так (в этот venv):
uv pip install --python "C:/Users/olegs/AppData/Local/hermes/hermes-agent/venv/Scripts/python.exe" <пакет>
```

Переменные окружения (все со значениями по умолчанию, трогать не обязательно):

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `NORMS_DB` | путь к SQLite | `data/normbase.db` |
| `QDRANT_URL` | инстанс Qdrant | `http://localhost:6333` |
| `NORMS_COLLECTION` | коллекция векторов | `norm_docs` (1024d, Cosine) |
| `NORMS_BGE_M3` | модель bge-m3 (ONNX) | `%LOCALAPPDATA%/hermes/models/bge-m3-onnx` |
| `NORMS_EMBED_THREADS` | потоки эмбеддинга | `8` |
| `NORMS_VISION_MODEL` | vision-модель для `figures --auto` | пусто = описывает агент |
| `NORMS_VISION_BASE_URL` | адрес API картинок | из Hermes config.yaml |
| `NORMS_VISION_API_KEY_ENV` | имя env-переменной с ключом | key_env провайдера |

Qdrant должен быть поднят — без него инжест не пройдёт (`status` покажет
`qdrant_points: недоступно`).

## 2. Добавить документ по ссылке

```bash
"$PY" norms.py add --code 'СП 131.13330.2018' \
                   --title 'Тепловая защита зданий' \
                   --url 'https://…/SP-131.13330.2018-….pdf'
```

Что печатает (реальный вывод, документ на 109 страниц):

```
[pdf] 7863586770_SP-60.13330.2020-….pdf | 1931555 байт | sha256 7863586770fc7014
[md] 287527 символов, 109 страниц -> СП_60.13330.2020.md
[chunk] 305 чанков, 422 уникальных пунктов (134 чанков несут больше одного пункта)
[embed] 16/305 | 0.3 текстов/сек
…
[embed] 305/305 | 0.5 текстов/сек
[done] СП 60.13330.2020: 305 чанков, 305 векторов, 305 точек Qdrant, 716.6 с
```

**Сколько ждать:** документ на 100–110 страниц — **~12 минут** (узкое место —
эмбеддинг на CPU: ~0.5 текстов/сек). Скачивание и конверсия занимают ~90 с,
остальное — вектора. На пачке ссылок запускать по очереди, фоном.

**Антибот.** Часть хостингов вместо PDF отдаёт HTML-челлендж (ServicePipe,
Cloudflare и т.п.). Парсер повторяет запрос **в той же сессии** до 5 раз с
растущей паузой — ход попыток видно в выводе:

```
[pdf] попытка 1/5: антибот-челлендж ServicePipe вместо PDF. Повтор через 2 с в той же сессии.
[pdf] 7863586770_SP-60.13330.2020-….pdf | 1931555 байт | sha256 …
```

Если все 5 попыток отвалились — скачать PDF руками (браузером) и отдать файлом:

```bash
"$PY" norms.py add --code 'СП 131.13330.2018' --title '…' --pdf 'D:/Загрузки/SP-131.13330.2018.pdf'
```

`--url` и `--pdf` взаимоисключающи (нужен ровно один).

**Код документа.** Лучше указывать точно: по нему потом идут ссылки
(`clause('СП 60.13330.2020', '7.6.9')`). Название кода обычно лежит на титульнике;
если не уверен — спросить у того, кто заказывает проверку.

## 3. Проверить, что документ лег нормально

```bash
"$PY" norms.py status
"$PY" norms.py docs
"$PY" norms.py clause 'СП 60.13330.2020' 7.6.9
```

Чек-лист приёмки (все пункты обязательны):

- [ ] `sync_delta: 0` и надпись `СИНХРОНО` — векторов столько, сколько чанков;
- [ ] `pending_embedding: 0` — не осталось чанков без вектора;
- [ ] в `docs` появилась строка нового документа, `indexed_at` — дата, а не `None`;
- [ ] `clause '<код>' '<номер>'` возвращает пункт, в цитате есть номер и страницы;
- [ ] `clauses` в `status` больше числа пунктов «на глазок» — проверить, что
      пропусков нет (для СП 60.13330.2020 вышло 422 пункта из 422 строк в MD);
- [ ] `tables` и `formulas` в `status` ненулевые (для СП 60 — 20 и 51),
      `pending_formulas` показывает, сколько формул ещё ждут описания.

Пример успешного `status`:

```
documents: 1
chunks: 305
clauses: 422
embedded: 305
pending_embedding: 0
figures: 2
tables: 20
formulas: 51
pending_formulas: 51
qdrant_points: 305
sync_delta: 0
СИНХРОНО
```

## 4. Искать

```bash
# hybrid (по умолчанию) — свободный текст вопроса
"$PY" norms.py search 'предел огнестойкости воздуховодов' -k 5

# векторный поиск с порогом (см. раздел «Пороги» README)
"$PY" norms.py search 'куда выбрасывать воздух' --mode semantic --threshold 0.58

# только точные формулировки (BM25)
"$PY" norms.py search 'предел огнестойкости' --mode keyword

# для агента: один JSON в stdout, прогресс глушится
"$PY" norms.py search 'пожарные клапаны' --json -k 3
"$PY" norms.py clause 'СП 60.13330.2020' 7.6.9 --json
```

Полезные флаги: `--limit N` (обрезка текста чанка, по умолчанию 400 символов),
`--full` (цитата целиком), `--doc '<код>'` (искать только в одном документе).

Режимы:

| Режим | Когда | Что даёт |
|---|---|---|
| `hybrid` | вопрос свободным текстом (по умолчанию) | RRF-слияние вектора и BM25 |
| `semantic` | перефразировки, синонимы | косинус bge-m3, работает `--threshold` |
| `keyword` | точная формулировка нормы | BM25 по FTS5 |
| `clause` | есть номер пункта | точная ссылка, порядок документа |

**Порог `score_threshold` = 0.58** для `--mode semantic` (калибровано на 11
запросах: цели 0.61–0.73, шум 0.47–0.54). Порог действует только в `semantic`;
в `hybrid` оценка RRF-овая и фильтруется не ею.

## 5. Если инжест оборвался (питон убит, таймаут, выключили машину)

Ничего переделывать не надо — база возобновляема:

```bash
"$PY" norms.py reembed        # доделывает чанки без вектора
"$PY" norms.py status         # снова sync_delta: 0
```

`reembed` берёт текст чанка из базы (`chunks.embed_text`), поэтому векторы
получаются точно такими же, как при непрерывном прогоне. Если процесс упал
**до** записи чанков (нет строки в `docs`) — запустить `add` заново: операция
идемпотентна, старые точки документа удаляются и заливаются заново.

## 6. Общие ошибки и что с ними делать

| Симптом | Причина | Действие |
|---|---|---|
| `сервер отдал не PDF … попытка 5/5` | хостинг режет по IP/гео | скачать файл руками → `--pdf` |
| `HTTP 403/404` | ссылка протухла или закрыта | взять актуальную ссылку |
| `модель bge-m3 не найдена` | нет весов ONNX | положить экспорт или задать `NORMS_BGE_M3` |
| `sync_delta: -N` | точек меньше чанков | `"$PY" norms.py reembed` |
| `sync_delta: +N` | остались точки удалённых/старых чанков | `add` того же документа заново (переиндексация идемпотентна) |
| `qdrant_points: недоступно` | Qdrant не запущен | поднять `localhost:6333` |
| в выводе `UnicodeDecodeError` в потоках | pymupdf4llm пишет CP1251 в stdout субпроцессов | не влияет на результат, можно не читать |
| ошибка `chunk` / `AttributeError` | старая версия модуля | `git pull`, проверить, что в `src/norms_base` актуальные файлы |

## 7. После нового документа

1. Прогнать чек-лист раздела 3.
2. Прогнать тесты: `"$PY" -m pytest tests -q` (загружают bge-m3, ~1–2 мин).
3. Если документов стало 2–3 — **повторить калибровку порога**: набрать
   5–10 заведомых запросов (по каждому известен правильный пункт), посмотреть
   `top-1` у `--mode semantic`, убедиться, что шум и цели не пересекаются.
   Числа в README, раздел «Пороги», обновить.
4. Добавить в README строку в «Источник» (код, название, URL).
5. Вырезать и описать картинки: `figures --extract`, затем `figures --pending`
   и `describe <id> --text` (или `figures --auto`, если задан `vision.model`),
   потом `reembed` → `СИНХРОНО` (раздел 9).
6. Таблицы и формулы при `add` извлекаются сами; для старых документов —
   `tables --extract` и `formulas --extract`, потом описать формулы
   (раздел 10) и `reembed`.

## 8. Чего делать нельзя

- **Не использовать Firecrawl/`web_extract` как источник текста норматива** —
  он искажает русский текст («отоления, ventilляции»). Только локальная
  конверсия через pymupdf4llm.
- **Не подмешивать другой эмбеддер.** Коллекция `norm_docs` — 1024d, модель
  bge-m3 (fp32 ONNX). Векторы другой модели (Ollama GGUF Q4, e5, nomic) в это
  пространство не встают: переход = полный переэмбеддинг всей базы.
- **Не править `data/` руками** — это артефакты (`pdf/`, `md/`, `*.db`), они
  восстановимы из URL/файлов; источник правды — SQLite + Qdrant.
- **Не запускать код проекта через `execute_code` Hermes** — там другой
  интерпретатор без pymupdf4llm/qdrant_client/onnxruntime. Только `$PY` из venv.

## 9. Картинки (изображения)

Конвейер вырезает из PDF картинки сам: растровые вставки и векторные схемы
с подписью «Рисунок N» (кроп страницы над подписью) кладутся в `data/img/<код>/`,
строки попадают в таблицу `figures`. При `add` это происходит автоматически;
для уже проиндексированных документов:

```bash
"$PY" norms.py figures --extract --doc 'СП 60.13330.2020'   # вырезать
"$PY" norms.py figures --pending                             # что ждёт описания
```

**Описывать — двумя способами (`figures.yaml`):**

1. `vision.model` пустая (по умолчанию) — режим агента: смотрит файл
   из вывода `figures` и заносит описание:
   `"$PY" norms.py describe 1 --text '…'`
2. `vision.model` задана — авто внешней LLM: `"$PY" norms.py figures --auto`
   (base_url/ключ берутся из Hermes config.yaml; разово без правки файла:
   `NORMS_VISION_MODEL=qwen/qwen3-vl-235b-a22b-instruct "$PY" norms.py figures --auto`).

Описание пишется в `figures` (переживает переиндексацию) и вшивается меткой
`<!-- fig:N --> … <!-- /fig:N -->` в текст чанка — оно попадает в FTS и в
эмбеддинг. После описания чанк помечен «без вектора», обязательный шаг:

```bash
"$PY" norms.py reembed && "$PY" norms.py status    # снова СИНХРОНО
```

Проверка: `norms.py search '<уникальная фраза из описания>' --mode keyword`
находит чанк с меткой.

## 10. Таблицы и формулы (данные для расчётных скриптов)

Эти объекты — источник правды для расчётно-проверочных скриптов: скрипт
берёт числа из `table_cells.num`, а не парсит текст чанка, и берёт формулу
из `formulas.expr`/`formulas.params`, а не сочиняет её по памяти.

```bash
# таблицы: список и ячейки (у старых документов сначала --extract)
"$PY" norms.py tables --extract --doc 'СП 60.13330.2020'
"$PY" norms.py tables                       # id, страницы, размеры, подписи
"$PY" norms.py tables --show 4              # шапка + строки raw/num

# формулы: кропы (при add режутся сами)
"$PY" norms.py formulas --extract --doc 'СП 60.13330.2020'
"$PY" norms.py formulas --pending           # список с путями к PNG
"$PY" norms.py formulas --set 6 --text 'Плотность приточного воздуха…' \
                         --expr '353/(273+t_h)' --params '{"t_h": "t наружного, °С"}'
"$PY" norms.py formulas --auto              # то же vision-моделью (figures.yaml)
"$PY" norms.py formulas --drop 12            # удалить ложную формулу
"$PY" norms.py formulas --md                 # переписать Markdown блоками формул
"$PY" norms.py reembed                      # ОБЯЗАТЕЛЬНО после описания
```

### Распознавание пачкой суб-агентами

`formulas --auto` шлёт кропы во внешнюю vision-модель по одному — медленно и
дорого на десятки формул. Второй путь: раздать кропы суб-агентам, каждый
смотрит картинку сам (`read` на PNG) и возвращает JSON. Импорт и запись в
базу делает координатор — параллельные писатели в SQLite не нужны.

```bash
"$PY" tools/formula_work.py split --parts 6   # data/formula_work/part_N.json
# ...суб-агенты читают part_N.json, пишут part_N.out.json по BRIEF.md...
"$PY" tools/formula_work.py import            # в базу: latex/expr/params/text
"$PY" norms.py formulas --md                  # LaTeX в Markdown
"$PY" norms.py reembed                        # метки вшиты в чанки
```

Формат пакета и требования к распознаванию — `data/formula_work/BRIEF.md`
(он же инструкция для агента). `drop: true` в ответе удаляет ложную запись
(заголовок таблицы, обрывок абзаца). `import` пишет `described_by=agent:subagent`.

Как это работает:

- **таблица** — это строки `tables` + ячейки `table_cells` (`raw` — что в
  документе, `num` — разобранное число, `NULL` если неоднозначно: «2/3»,
  «–»), плюс подпись, страницы и `chunk_id`-носитель (`kind=table`);
- **формула** — строка `formulas` (номер «А.6», страница, якорный текст)
  и PNG-кроп в `data/img/<код>/f_pNNN_KK.png`; распознавание (`latex`,
  `expr`, `params`, `description`) заполняет агент (`--set`) или vision-модель
  (`--auto`);
- **`latex_geom`** — LaTeX, восстановленный при извлечении по геометрии
  символов (`mathlayout.py`): черта дроби из `get_drawings`, степени и индексы
  по кеглю и смещению базовой линии, глифы SymbolMT по таблице соответствий.
  Это черновик без LLM: он есть у всех формул, но в Markdown попадает только
  после проверки качества (`_sane_geometry`: сбалансированные скобки, нет
  обрывков объяснений и битой кодировки, нет потерянных цифр). Не прошёл —
  в Markdown остаётся кроп, а `latex_geom` можно посмотреть в `--json`
  и поправить руками через `--set --latex`;
- описание вшивается меткой `<!-- fml:N -->` в чанк → находится FTS и
  вектором вместе со своим пунктом; после этого чанк «без вектора» —
  `reembed` → `СИНХРОНО` (проверять через `status`, не на глаз);
- **Markdown тоже несёт формулы**: `add` и `--md` ставят в `data/md/<код>.md`
  блок `<!-- fml-md:А.6 --> … <!-- /fml-md:А.6 -->`. Внутри — LaTeX в `$$…$$`
  в порядке приоритета: `latex` (модель/агент) → `latex_geom` (геометрия,
  рядом остаётся кроп для сверки) → выражение `expr` → ссылка на кроп PNG.
  Блок встаёт над строкой-номером, а если номер конвертер потерял — по якорному
  тексту («…по формуле»); ни к чему не привязанные формулы уходят в раздел
  «Формулы, извлечённые из PDF» в конце. Вставка идемпотентна: повторный
  `--md` даёт тот же файл;
- для агента все команды принимают `--json` (сторонний вывод вроде
  RapidOCR уходит в stderr, stdout — чистый JSON).

## 11. Мини-шпаргалка

```bash
cd /d/DEV/spT00db
PY="C:/Users/olegs/AppData/Local/hermes/hermes-agent/venv/Scripts/python.exe"

"$PY" norms.py add --code 'СП …' --title '…' --url 'https://…/x.pdf'   # инжест (~12 мин)
"$PY" norms.py status                                                   # СИНХРОНО?
"$PY" norms.py docs                                                     # что в базе
"$PY" norms.py clause 'СП 60.13330.2020' 7.6.9                          # точный пункт
"$PY" norms.py search 'запрос' -k 5                                     # hybrid-поиск
"$PY" norms.py search 'запрос' --json -k 3                              # для агента
"$PY" norms.py reembed                                                  # доделать после обрыва
"$PY" norms.py figures --pending                              # картинки без описания
"$PY" norms.py describe 1 --text '…'                          # описать картинку (агент)
"$PY" norms.py figures --auto                                 # автоописание LLM
"$PY" norms.py tables --show 4                                # ячейки таблицы с num
"$PY" norms.py formulas --pending                             # формулы без описания

"$PY" norms.py formulas --md                                  # формулы в Markdown
"$PY" tools/formula_work.py split --parts 6 && … import       # пачкой суб-агентами
"$PY" -m pytest tests -q                                                # smoke-тесты
```
