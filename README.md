# spT00db — база нормативных документов

Библиотека СП/ГОСТ/СанПиН в SQLite + Qdrant, чтобы агент-проверяющий мог сверять
проектную документацию с нормами: семантический поиск по смыслу, лексический по
формулировкам и точный переход по номеру пункта («п. 7.6.9»).

Точка входа — CLI `norms.py`: подкоманды `add/search/clause/docs/status/reembed`,
флаг `--json` отдаёт результат машиночитаемо (для агента).

## Схема

```
PDF (URL, антибот-обход) или локальный --pdf
  -> pymupdf4llm page_chunks      постраничный Markdown + номер страницы
  -> convert.clean_page           чистка колонтитулов/номеров/отметок редакции
  -> convert.join_pages           склейка страниц: рванные абзацы и таблицы
  -> chunk.chunk_markdown         чанки по ПУНКТАМ нормы (граница = п. 7.6.9, таблица)
  -> SQLite (data/normbase.db)    documents + chunks + chunk_clauses + FTS5 (BM25)
  -> bge-m3 ONNX (1024d, L2)      батчи по 16, 8 потоков, CPU, локально
  -> Qdrant norm_docs             payload: doc_code, clause_id, clause_ids, page_*, text
```

Почему три слоя поиска:

| Режим | Что даёт | Пример запроса |
|---|---|---|
| `clause` | точная ссылка, порядок документа | `('СП 60.13330.2020', '7.6.9')` |
| `keyword` | BM25 по FTS5 — точные формулировки | «предел огнестойкости воздуховодов» |
| `semantic` | bge-m3 — синонимы, перефразировки | «куда выбрасывать воздух из вентиляции» |
| `hybrid` | RRF-слияние (по умолчанию) | свободный текст вопроса |

**Пункты в чанке не теряются.** Склейка мелких пунктов кладёт 7.6.8, 7.6.9 и
7.6.10 в один чанк, поэтому в таблице `chunk_clauses` хранится соответствие
«чанк ↔ все его пункты», и `clause('…', '7.6.9')` находит пункт, даже когда
primary-номер чанка — 7.6.8. В выдаче `clause_id` — запрошенный номер
(корректная цитата), `clause_ids` — соседи по чанку.

## Структура

```
norms.py         CLI: add/search/clause/docs/status/reembed + --json
src/norms_base/
  config.py      пути/константы (DB_PATH, QDRANT_URL, COLLECTION=norm_docs,
                 EMBED_BATCH=16, EMBED_THREADS=8, размеры чанков)
  download.py    fetch_pdf: cookies корня + Referer + Sec-Fetch-* + повтор
                 в ТОЙ ЖЕ сессии (антибот-челлендж ServicePipe)
  convert.py     pdf_to_markdown: построчная чистка, карта (offset -> страница)
  chunk.py       chunk_markdown: границы по пунктам/таблицам, build_embed_text
  embed.py       Embedder: bge-m3 ONNX, ленивая сессия, L2-нормализация
  storage.py     Store: SQLite schema, FTS5, chunk_clauses, find_clause/search_fts
  vectorstore.py VectorStore: Qdrant, payload-индексы, point_id = uuid5(code:ord)
  pipeline.py    add_document(): PDF -> ... -> Qdrant, reembed_pending(), status()
  search.py      API для агента: clause/section/keyword/semantic/hybrid/docs
tests/           smoke: конверсия фикстуры -> чанки -> FTS -> вектор -> hybrid -> статус
data/            (в .gitignore) normbase.db, pdf/, md/ — артефакты, восстановимы
```

## CLI

```bash
PY="C:/Users/olegs/AppData/Local/hermes/hermes-agent/venv/Scripts/python.exe"

# проиндексировать документ (URL с обходом антибота или локальный файл)
"$PY" norms.py add --code 'СП 60.13330.2020' --title 'Отопление, вентиляция и кондиционирование воздуха' --url 'https://…/SP-60.13330.2020-….pdf'
"$PY" norms.py add --code 'СП 60.13330.2020' --title '…' --pdf data/pdf/файл.pdf

# поиск (по умолчанию hybrid; --mode semantic|keyword)
"$PY" norms.py search 'предел огнестойкости воздуховодов' -k 5
"$PY" norms.py search 'куда выбрасывать воздух' --mode semantic --threshold 0.35

# точный пункт, статус, возобновление после обрыва
"$PY" norms.py clause 'СП 60.13330.2020' 7.6.9
"$PY" norms.py status
"$PY" norms.py reembed

# для агента: один JSON в stdout, прогресс глушится
"$PY" norms.py search 'пожарные клапаны' --json -k 3
```

`--limit N` (по умолчанию 400 символов) режет текст чанка в выдаче, `--full`
отдаёт цитату целиком; полный текст любого чанка — `search.get_text(chunk_id)`.

## Статус (2026-10-07)

**Сделано**

- `src/norms_base/` — 10 модулей, все импортируются; `norms.py` — CLI со всеми
  подкомандами и `--json`.
- Первый end-to-end прогон: `add_document('СП 60.13330.2020', …)` -> SQLite + Qdrant,
  `status()` даёт `sync_delta = 0`.
- Точная ссылка работает: `clause('СП 60.13330.2020', '7.6.9')` находит пункт,
  `clause(..., 'А.1')` — пункты приложений; таблица Приложения П лежит одним чанком.
- Smoke-тесты `tests/`: конверсия фикстуры -> чанки -> FTS -> вектор в тестовой
  коллекции -> hybrid -> статус -> идемпотентный повторный инжест.
- Конверсия сверена на СП 60.13330.2020: 109 страниц, 422 пункта из 422 сохранено,
  13 приложений (А–П), ноль колонтитулов, ноль отметок редакции, ноль номеров страниц.
- Эмбеддер замерен на реальных чанках (см. «Грабли»): старые цифры «67 текстов/сек»
  относились к коротким запросам и на длинных чанках не работают.
- Скачиватель устойчив к антибот-челленджу ServicePipe (повтор в той же сессии).

**Не сделано / ограничения**

- Второй и последующие документы ещё не инжестовались (процедура ниже).
- Калибровка порога сделана на одном документе; после 2-3 инжестов повторить.

## Как подключить следующий документ

1. Найти URL PDF норматива (или положить файл локально и взять `--pdf`).
2. Проиндексировать:
   `"$PY" norms.py add --code 'СП 131.13330.2018' --title '…' --url '…'`.
   Если хостинг отдаёт антибот-челлендж — `fetch_pdf` повторяет в той же сессии
   (5 попыток с растущей паузой), ход попыток печатается в вывод.
3. Проверить: `"$PY" norms.py status` -> `sync_delta: 0`, `"$PY" norms.py docs` ->
   новая строка, `"$PY" norms.py clause '<код>' '<пункт>'` -> пункт найден.
4. Если инжест прервали — `"$PY" norms.py reembed` доделывает чанки без вектора
   и снова помечает документ проиндексированным.
5. Скачанный PDF и Markdown — артефакты (`data/`, в `.gitignore`): их отсутствие
   не ломает поиск, источник правды — SQLite + Qdrant.

## Пороги

Калибровка `score_threshold` для `--mode semantic` (2026-10-07, один документ,
11 запросов: 8 заведомо нужных + 3 заведомо чужих):

| запрос | top-1 |
|---|---|
| предел огнестойкости транзитных воздуховодов | 0.719 (Приложение Н) |
| расчет тепловых нагрузок на систему отопления | 0.726 (Приложение А) |
| требования к воздушным завесам | 0.693 (п. 7.8) |
| минимальный воздухообмен в жилых помещениях | 0.668 (п. 7.3.2) |
| температура воздуха в вестибюле при воздушном отоплении | 0.657 (п. 7.8) |
| куда выбрасывать воздух из вентиляции | 0.626 (п. 7.3.17) |
| кратность воздухообмена для кухни с газовой плитой | 0.617 (п. 7.10.23) |
| пожарные клапаны в противопожарных преградах | 0.611 (п. 7.11.8) |
| — шум: изыскания для строительства | 0.488 |
| — шум: арматура ЖБК по СП 52-101 | 0.537 |
| — шум: аттестация области аккредитации | 0.471 |

**Рекомендуемый порог — 0.58**: проверено прогоном всех 11 запросов —
целевые 8/8 возвращают результат, чужие 3/3 отсекаются полностью.
Зазор узкий (0.537 шум ↔ 0.611 цель), поэтому порог — «на грани»: при
появлении второго документа в базе калибровку повторить.

`hybrid` (по умолчанию) порога не использует — там RRF-оценка, которая
считается из рангов, а не из косинуса; порог имеет смысл ставить только
в `--mode semantic`. На проверенных запросах hybrid ставит авторитетные
разделы выше семантики (например, «минимальный воздухообмен» -> Приложение В,
а не п. 7.3.2).

## Грабли, на которые уже наступили

- **Антибот ServicePipe, а не «Forbidden».** Хостинг (nav.tn.ru) отдаёт HTML-челлендж
  (1892 байта, скрипт servicepipe.tech) примерно в одном запросе из трёх. **Ответ с
  челленджа сам ставит cookies `spid`/`spst`**, поэтому повтор обязан идти в ТОЙ ЖЕ
  сессии: повтор в новой сессии стартует без cookies и снова получает челлендж.
- **`web_extract` (Firecrawl) искажает русский текст** этого PDF («отоления,
  ventilляции», «жилинно-коммунального») — локальная экстракция через pymupdf4llm
  даёт чистый текст. Не использовать Firecrawl как источник текста нормативов.
- **Эмбеддинг — самая дорогая часть конвейера.** Замер на СП 60.13330.2020 (16 логических
  ядер): поштучно 3.2 с/чанк, батч из 16 при 8 потоках — 2.3 с/чанк; батчи длиннее 16
  не помогают (паддинг до самого длинного в группе). Полный инжест ~12 минут на 305 чанков.
  Потоки >8 хуже: `intra=16` даёт 29 с против 18 с на батче из 8 текстов.
- **pymupdf4llm**: `page_chunks=True` -> элементы с `metadata.page_number` и `text`;
  в доках сигнатура обёртки `(*args, **kwargs)`, поэтому `inspect.signature` не поможет.
- **Субпроцессы pymupdf4llm** кидают `UnicodeDecodeError` в потоках чтения stdout
  (кодировка CP1251 у вывода) — не влияет на результат, но в pytest даёт варнинги
  `PytestUnhandledThreadExceptionWarning` (гасятся `-p no:warnings`).
- **Qdrant**: чтение payload — `POST /collections/{c}/points/scroll` (GET отвергается).
- **`execute_code` (ядро Hermes) — другой интерпретатор**, в нём нет
  pymupdf4llm/qdrant_client/onnxruntime; запускать код проекта через
  `C:/Users/olegs/AppData/Local/hermes/hermes-agent/venv/Scripts/python.exe`.
- **Ставить пакеты** в этот venv: `uv pip install --python "...venv/Scripts/python.exe" <pkg>`.
- **Многострочный код через `python -c`** в git-bash не проходит (bash оставляет `\n`
  буквами даже после `json.dumps`) — писать скрипт в файл и запускать файл.
